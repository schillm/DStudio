# DStudio 1017 (fork)

This fork of [DStudio](https://github.com/sk8erboi17/DStudio) adds support for
**DeepSeek-V4.1-Flash-1017** on Apple Silicon, using the community ds4 GGUF quant, and builds as a
separate app, **DStudio 1017**, that can run alongside a stock DStudio install.

Base: upstream `f8f84f5` (October 3, 2026). Everything here is macOS/Metal only, like upstream V4.1.

## What it adds

- **DeepSeek V4.1 Flash 1017 Q2 + its vision sidecar** as two new downloads in Settings → Models
  (targets `ds41f-1017-q2`, `ds41f-1017-vision`). Source:
  [`nazeshinjite/DeepSeek-V4.1-Flash-1017-ds4-GGUF`](https://huggingface.co/nazeshinjite/DeepSeek-V4.1-Flash-1017-ds4-GGUF),
  pinned to revision `796f585`, made with ds4's stock `deepseek41_quantize.py --quant q2` recipe
  (layout identical to antirez's V4.1 Q2). `scripts/download-ds41-1017.sh` downloads with the
  Hugging Face CLI at the pinned revision and verifies exact size and SHA-256; a file that fails
  verification is never admitted. The 1017 model gets the same V4.1 runtime rules as stock V4.1
  (SSD streaming, context limit, no DSpark), and only ever pairs with its own vision sidecar.
- **Vision for 1017** via [antirez/ds4 PR #1225](https://github.com/antirez/ds4/pull/1225), applied as a
  managed DStudio patch (`patch/ds4-v41-vision-pairing/`, `scripts/apply-ds4-v41-vision-pairing.sh`).
  Upstream ds4 at DStudio's pin hard-codes the original V4.1 checkpoint for vision; the patch pairs
  the sidecar with the language GGUF by `general.source.revision`. It is reversible, idempotent, and
  becomes a no-op once upstream ds4 contains the change. The vendored `src/engines/ds4` is untouched.
- **Separate app identity**, so it can coexist with stock DStudio: `DStudio1017.app`, bundle id
  `dev.ds4.DStudio1017`, data dir `~/Library/Application Support/DStudio 1017`, its own
  single-instance lock, chat history and prompt (KV) cache, web port 5517 and engine port 28017
  (constants in `src/dstudio_identity.h`).
- **Shared weights only.** The fork's `ds4/gguf` is a symlink to the stock
  `~/Library/Application Support/DStudio/ds4/gguf` when that folder exists, so models are not
  downloaded twice. The fork never deletes, moves or rewrites stock files: it refuses engine checkouts
  inside the stock support folder, only lists/resumes/deletes partial downloads it started itself,
  and leaves partials written in the last two minutes alone.

Intentionally still shared with a stock install: the ds4 model lock (`/tmp/ds4.lock`, so only one
large model runs at a time), user skills, `~/.dstudio` media tools and caches, and the GPU
wired-memory LaunchDaemon. If the stock app holds the model lock, the fork says so instead of
waiting silently (Agent/Design/Cowork engines of the stock app may still show "Attaching…").

## Build

```sh
git clone -b v41-1017 https://github.com/schillm/DStudio.git dstudio-1017
cd dstudio-1017
make app            # produces DStudio1017.app (ad-hoc signed)
open DStudio1017.app
```

Do not use `scripts/install-macos.sh` here (it installs upstream's release; the script refuses to
run in this fork). On first launch, install the engine at the default location; then download the
1017 Q2 (~341 GiB) and vision file (~0.9 GiB) from Settings → Models. On a 128 GB Mac use SSD
streaming; antirez recommends starting at a 32K context for V4.1 Q2 on one 128 GB Mac.

## Status and caveats

- Community quant: same recipe and layout as antirez's Q2, calibrated with Lucebox's public 1017
  imatrix rather than antirez's. Not independently quality-tested here.
- Upstream DStudio has not finished its own V4.1 Q2 qualification (see `docs/DS41_UPDATE_CHECKPOINT.md`);
  1017 inherits that status.
- Linux-runnable unit and integration tests for the new code pass; macOS-only paths were exercised by
  building and running on an Apple Silicon Mac, not by an automated macOS test run.
- Pre-existing upstream test failures (`agent_build_test`, `launch_control_http_test`) are unchanged.
